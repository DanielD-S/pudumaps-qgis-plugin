changelog=0.7.13 (2026-05-19) — Fix extract_buildings flow + mejor mensaje vacío
  * BUG REPORTADO en 0.7.12: extract_buildings corría 1 min y fallaba
    silenciosamente con "geoai no produjo el archivo de máscaras".
    Causa: mi código asumía que process_raster() escribe un GeoTIFF
    de máscaras intermedio (entonces vectorizar después), pero
    realmente process_raster() es la pipeline COMPLETA: tile, infer,
    vectorize, escribir GeoJSON. Devuelve GeoDataFrame directo.
  * Rewrite: ya no se genera _masks.tif intermedio. process_raster
    se invoca con output_path=geojson y listo. Si devuelve None pero
    escribió, leemos el GeoJSON. Si no escribe nada (0 detecciones),
    mensaje explícito al usuario con sugerencias (orto ≤1m/px en vez
    de Sentinel 10m/px).

 0.7.12 (2026-05-18) — Auto-uninstall pyarrow + RGB renderer
  * BUG CULPABLE IDENTIFICADO: pyarrow.lib choca con DLLs C++ de QGIS
    causando "DLL load failed while importing lib". Auto-uninstall en
    el cleanup post-instalación (sklearn lo importa defensivamente y
    cae sin él — no afecta acciones IA).
  * Sentinel-2 descargado ahora se carga con renderer multibanda
    R=1/G=2/B=3 + stretch min-max automático. Antes se veía negro
    porque QGIS default lo cargaba en grayscale.

 0.7.11 (2026-05-18) — Fix MKL conflict + GeoAgent pin
  * BUG REPORTADO: DLL load failed se mantiene incluso en main thread.
    Causa real: conflicto MKL/OpenMP entre QGIS y PyTorch (no
    threading como pensé en 0.7.9). Fix: warm_up_geoai ahora setea
    KMP_DUPLICATE_LIB_OK=TRUE y registra torch/lib como dll_directory
    ANTES de `import geoai`.
  * BUG REPORTADO: pin GeoAgent==0.4.0 no existía en PyPI (versiones
    reales saltan de 0.2.0 a 1.0.0). Bump a 1.8.0 (última).
  * Sin cambios funcionales nuevos — todos los rewrites de tools de
    0.7.10 siguen igual.

 0.7.10 (2026-05-18) — Rewrite wrappers + warm-up + UX polish
  * Rewrite de las 5 acciones IA con APIs reales de geoai 0.10.0:
    BuildingFootprintExtractor.process_raster (no predict),
    ChangeDetection.detect_changes (no ChangeDetector),
    CLIPSegmentation con text prompt para water (no WaterBodyExtractor),
    image_segmentation HF para landcover (marcado experimental),
    pystac-client + planetary-computer para download Sentinel-2.
  * Warm-up de geoai en main thread (fix DLL load en QgsTask Windows).
  * PyTorch CPU-only forzado desde índice oficial PyTorch (evita
    DLL CUDA fail en máquinas sin GPU NVIDIA).
  * Barra de progreso real con tiempo + MB + paquete N/M durante
    instalación pip.
  * Ventana consola cmd oculta vía CREATE_NO_WINDOW.

 0.7.8 (2026-05-18) — Hotfix robusto: detección Python QGIS
  * El fix de 0.7.7 (usar sys.prefix) no cubría todas las layouts de
    QGIS-Windows: algunas distribuciones tienen sys.prefix apuntando
    al root de QGIS, no al directorio del Python embebido.
  * Estrategia más robusta: usar os.__file__ (que SIEMPRE apunta a
    <python_root>/Lib/os.py) para derivar el python.exe correcto.
    Fallbacks múltiples si esto falla.
  * Defensa adicional: el instalador valida que el python resuelto
    sea un archivo real antes de invocar subprocess. Si la detección
    falla, error claro en vez del críptico "could not be found".
  * Diagnóstico al inicio del log de pip: [pudumaps-ai diagnostics]
    con sys.executable / sys.prefix / resolved_python para que los
    reportes de bug traigan siempre el contexto necesario.

 0.7.7 (2026-05-18) — Hotfix: instalador IA en Windows
  * BUG CRÍTICO: en QGIS-Windows sys.executable apunta al binario GUI
    (qgis-bin.exe), no a python.exe. El instalador IA de 0.7.6 fallaba
    "relanzando QGIS" en vez de invocar pip, con error críptico
    'geoai-py==0.10.0 could not be found' (QGIS interpretaba la spec
    como archivo de proyecto). Ahora deriva python.exe desde sys.prefix
    que sí apunta consistentemente al Python embebido.
  * Sin cambios funcionales. Tests +4.

 0.7.6 (2026-05-18) — Download Sentinel-2 + cierre 5 acciones
  * Quinta y última acción del plan IA original: "Descargar
    Sentinel-2" (DownloadSentinelTool). Bbox del canvas (o custom

    download_sentinel. v0.8.0 arranca con Nivel 2 chilenización

 0.7.5 (2026-05-18) — Change detection + framework prompt_params
  * Cuarta acción IA: "Detectar cambios (2 rásters)"
    (ChangeDetectionTool). Compara dos rásters del mismo bbox y
    distinta fecha, produce máscara binaria de cambios.
  * Nuevo patrón en AITool: input_kind='none' + prompt_params(parent,
    iface) hook. Permite tools que no usan la capa activa y necesitan
    pedir input vía diálogo propio. Útil también para futuros tools
    que requieran fechas, bbox custom, etc.
  * Diálogo selector dialogs/change_detection_dialog.py lista los
    rásters del proyecto y pide "antes" y "después" con validación
    (no permite el mismo, requiere ≥2 rásters cargados).

 0.6.0 (2026-05-07) — Security hardening (audit 2026-05-07)
  * H1 ALTO: prompt explícito antes de degradar a almacenamiento
    plaintext de QSettings cuando QgsAuthManager no tiene master
    password. Antes el fallback era silencioso.
  * H2 ALTO: rechazo de URLs base no-HTTPS (excepto loopback). Previene
    leak de la API key si el user/atacante setea http://evil.example/
  * H3 MEDIO: tempfile usado por OGR ahora se borra en finally. Solo
    sobrevive cuando OGR es la layer activa y necesita leerlo on-demand
    (caso fallback).
  * H4 MEDIO: cap de 50 MB en respuestas HTTP + validación estructural
    de GeoJSON antes de pasar a OGR. Previene OOM por payloads
    malformados.
  * H5 MEDIO: helper safe_error_message en todos los diálogos. Stack
    traces y mensajes técnicos de la API ya no se muestran al usuario;
    el detalle queda en QgsMessageLog para debugging.
  * H6 BAJO: User-Agent leído dinámicamente desde metadata.txt. Antes
    estaba hardcoded a 0.1.0.
  * H8 BAJO: clear_credentials retorna ahora True/False según pudo
    eliminar la entry cifrada. SettingsDialog avisa al user si quedó
    residuo cifrado por falta de master password en sesión.
